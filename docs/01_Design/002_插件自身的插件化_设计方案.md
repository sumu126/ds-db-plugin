# 002_插件自身的插件化_设计方案

> 目标：把 `dsh-ds-db` 自己也变成「一切皆插件」——核心只提供方言注册表与工具，**每种数据库类型都是一个平级的方言包**，MySQL 也不例外。

## 1. 重构前的问题

MySQL 是核心的**私有实现**：

```
src/index.ts  ──import──▶  src/dialect-mysql.ts      ← 核心认识 MySQL
src/          └─ dependencies: mysql2                ← 核心背上了驱动
```

后果：

1. **两套标准**：核心自带 MySQL，第三方却要发独立包。MySQL 走的是"内部路径"，第三方走的是"外挂路径"，前者能拿到核心的内部便利，后者不能——这本身就否定了 seam 的公平性。
2. **驱动强绑**：`mysql2` 在核心 `dependencies` 里，任何只想用别的数据库的人也要装它。
3. **没有范式**：写新方言的人在本仓找不到"一个方言包长什么样"的样板，只能读 `examples/`，而 examples 不在 workspace 里，导入方式都不对。

## 2. 目标结构

```
ds-db-plugin/
├── package.json            # 根 = 核心（dsh-ds-db）：seam、工具、设置页、审计
├── pnpm-workspace.yaml     # packages: ['.', 'dialects/*', '!dialects/_template']
├── src/                    # 核心不含任何方言，也不依赖任何驱动
├── dialects/               # ★ 数据库类型工作区
│   ├── mysql/              #   dsh-dialect-mysql（官方，随主包自动安装）
│   ├── _template/          #   新方言的起手骨架（不是包）
│   └── <第三方>/            #   官方/合作方言可进这里；外部第三方复制模板出仓
```

`examples/` 已移除：`dialects/mysql` 本身就是比它更完整的真实实现，保留两套标准只会让"该照哪个抄"变模糊。

## 3. 三个关键机制

### 3.1 方言按包名解析核心 API

方言包 `import { ... } from 'dsh-ds-db/src/dialect.ts'`，靠 workspace 的 `dsh-ds-db: "workspace:*"` 链接到 `node_modules` 解析。

> 这解决了此前实测发现的问题：仓外包在源码态加载时，裸导入没有解析机制（`examples/dsh-dialect-postgres` 只能退回相对路径）。进入 workspace 后，**与出仓发布后的解析方式完全一致**。

### 3.2 MySQL 由加载器挂载，不由代码 import

核心 `cordis.patch.yml` 两行：

```yaml
- insert:
    - id: dialect-mysql
      name: 'dsh-dialect-mysql'
    - id: ds-db
      name: 'dsh-ds-db'
```

核心 `dependencies` 加 `dsh-dialect-mysql`，用户仍只装一个包；但结构上 MySQL 已经是"一个被加载的方言包"。

### 3.3 工具注册等待方言就绪

工具描述在**注册时写定**，内容来自方言自己的事实（自称、放行语句族、行数上界写法）。核心不再持有方言对象，因此：

```ts
ctx.effect(() => {
  const waiting = registry.whenRegistered(initialDialect, registerTools)
  const timer = setTimeout(registerTools, DIALECT_WAIT_MS)   // 100ms 兜底
  timer.unref?.()
  return () => { waiting(); clearTimeout(timer) }
})
```

- 正常路径：方言包先注册 → 工具立即注册，描述一次写对
- 异常路径：配置的方言包缺失或名字写错 → 100ms 后用**兜底事实**注册工具，调用时报出「方言未注册，已注册的是 X」

注册表为此新增 `whenRegistered(name, listener)`，`register()` 同步唤醒等待者。

## 4. 兼容性

| 面 | 变化 | 影响 |
| --- | --- | --- |
| `DatabaseDialect` 接口 | 无变化 | 方言实现不受影响 |
| 工具与设置页 | 无变化 | 用户无感 |
| 用户安装 | 仍只装 `dsh-ds-db` | 无变化 |
| 核心 `dependencies` | `mysql2` → `dsh-dialect-mysql` | 核心变小 |
| 工具描述 | 由方言事实写定（原先由核心内置方言写定） | 正常部署下文本不变 |
| `described` 类型 | `DatabaseDialect` → `DialectFacts` | 内部接口收窄 |

- 核心的 `KNOWN_DIALECT_PACKAGES` 仍是常量清单；将来若有一个"方言包的 npm 搜索"机制，可以改为动态读取
