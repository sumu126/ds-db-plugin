# 003_默认值与自述的归属_设计方案

> 目标：把「端口 3306、账号 root、类型叫 MySQL」这最后一层偏心从插件里摘掉——**默认值是服务器的事实，不是只读数据库访问的事实**。

## 1. 触发这次改动的问题

002 把 MySQL 变成了普通方言包，但核心仍留了四处"知道 MySQL 长什么样"的地方：

| # | 位置 | 症状 |
| --- | --- | --- |
| 1 | `client/form.ts` 的 `blankFields()` | 新建**任何**类型的连接都预填 `port: '3306'`、`user: 'root'`、`name: 'MySQL'` |
| 2 | `DatabaseSettingsPage.tsx` 的类型卡片 | `configFields.length === 0 ? t('dialectMysqlDesc')` —— 任何没有专属字段的方言都会印上 "Connects through the mysql2 driver"（**编造描述**） |
| 3 | `dialect-catalog.ts` | `DEFAULT_DIALECT_NAME = 'mysql'`；组合层默认连接 `name: 'MySQL'`、`MYSQL_DEFAULTS`（3306/root） |
| 4 | `client/form.ts` | `DIALECT_OFFERINGS` 硬编码类型清单（页面已改用 host 目录，是死代码） |

根因是同一个：**共享连接字段的默认值写在核心，而它们恰好是 MySQL 的取值**。方言只能声明自己专属字段的默认值，没地方声明共享字段的。

## 2. 设计：默认值归方言，自述归方言

### 2.1 `connectionDefaults`（新增）

```ts
interface DatabaseDialect {
  /** 该方言对共享连接字段的默认取值。 */
  readonly connectionDefaults?: ConnectionDefaults   // { host?, port?, user?, database?, passwordEnv? }
}
```

用途两处：

1. **页面预填**：选中类型后，新建连接的表单用它的值初始化（`blankFields(descriptor, dialect)`）
2. **连接回落**：已保存的连接里留空的字段，解析连接时回落到它

两者都不命中时——**明确拒绝并点名缺失字段**，而不是由插件猜：

```
connection "生产库" has no port, and PostgreSQL declares no default for it
```

### 2.2 `description`（新增）

类型卡片的一行说明由**方言自己写**（`DatabaseDialect.description`），页面经 catalog 读取渲染。插件不再有任何"某类型连接什么"的文案——因为它不该知道。

### 2.3 端口用 `UNSET_PORT = 0` 表示"未设置"

`port: 0` 是合法的 schema 值（`z.natural()`），语义是"用方言的默认值"。这样组合层的默认连接不必携带 3306：

```ts
// 核心的共享默认值：一个也不属于任何数据库
export const SHARED_DEFAULTS: ConnectionProfile = {
  id: 'default', name: 'default', dialect: '',   // 空 = 部署里第一个注册的方言
  extra: {}, host: '127.0.0.1', port: UNSET_PORT, user: '', database: '',
  passwordEnv: 'DSH_DB_PASSWORD',                 // 引用名也不再叫 MYSQL
  connectTimeoutMs: 10_000, queryTimeoutMs: 30_000, maxRows: 200,
}
```

### 2.4 空方言名 = 第一个已注册方言

`resolveDialect(registry, '')` 返回 `registry.first()`；`dialectFacts(registry, '')` 同规则，**因此描述与调用读的是同一个方言**。注册表的 `whenRegistered('')` 变成"等任意方言"，与解析语义一致。

组合层于是可以完全不写 `dialect:`，插件也能工作——只要部署里装了至少一个方言包。

若一个都没有：

```
no database dialect is registered; install a dialect package, such as dsh-dialect-mysql
```

### 2.5 命名残留一并清掉

| 旧 | 新 |
| --- | --- |
| `MYSQL_SETTINGS_NAMESPACE` / `MYSQL_TEST_PATH` / `MYSQL_DIALECTS_PATH` | `DB_SETTINGS_NAMESPACE` / `DB_TEST_PATH` / `DB_DIALECTS_PATH` |
| `MysqlSettings` | `ConnectionProfile` |
| `MysqlLocaleKey` / `MysqlCredentialsFace` | `DbLocaleKey` / `DbCredentialsFace` |
| `DEFAULT_PASSWORD_REF = 'DSH_MYSQL_PASSWORD'` | `'DSH_DB_PASSWORD'`（MySQL 方言在自己的 `connectionDefaults` 里声明 `DSH_MYSQL_PASSWORD`） |
| 字典命名空间 `settings.mysql` | `settings.db` |
| `MYSQL_DEFAULTS` | `SHARED_DEFAULTS` |

`MysqlSettings` 出现 20 余处、`MYSQL_*` 10 余处，全部为内部标识符，无外部消费者。

## 3. 兼容性

| 面 | 影响 |
| --- | --- |
| 已保存的连接 | 不变。`dialect: 'mysql'` 仍解析得到 MySQL；字段有值就不会走回落 |
| 已保存的凭据 | 不变。`passwordEnv` 是连接字段，值仍是 `DSH_MYSQL_PASSWORD` |
| `cordis.yml` 平铺字段 | 不变，仍可写 `host`/`port`/`dialect` |
| 新建连接的默认值 | **变了**：从"固定 MySQL 值"变成"所选方言的值" |
| 组合层不写 `dialect` | **新增可行**：落到第一个已注册方言 |

## 5. 补充：`UNSET_PORT` 不得漏到界面（同日修复）

引入 `UNSET_PORT = 0` 后出现一个展示缺口：组合层没写 `port` 时，连接文档里存的是 `0`，而**界面与工具清单直接打印了这个原始值**——设置页卡片显示 `127.0.0.1:0`，`db_connections` 报 `port: 0`；编辑表单更糟，`0` 过不了正整数校验，**编辑已有连接会无法保存**。

修法：界面与模型看到的一律是**生效值**（连接值 ‖ 方言默认值），由 `effectiveConnection(profile, defaults)` 统一计算，四处共用：

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| `db_connections` | 原始 `port: 0` | 解析后的 `3306`（方言未注册时退回原始值，不让清单失败） |
| 设置页卡片 | `127.0.0.1:0` | `127.0.0.1:3306` |
| 编辑表单 | 端口框 `0`（无法保存） | `3306`，保存即写实 |
| 工具调用 | 已正确回落 | 不变 |

`0` 于是只在"文档"这一层短暂存在，用户与模型看到的都是真实目标。回归断言：组合层不写 `port` 时，`db_connections` 必须报 `3306`。

## 6. 现在的规则

> **插件只知道"连接"这件事；端口、账号、默认库、类型描述，全部是方言的声明。**
> 方言不声明，就由用户填；用户也不填，调用报出缺的是哪个字段。
