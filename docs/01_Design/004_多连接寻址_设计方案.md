# 004_多连接寻址_设计方案

> 目标：让**模型**也能在多条已保存连接之间选择，而不只是用户在页面切换。

## 1. 之前的状态

设置页能存多条连接，但工具只认一条：

```
db_query(sql)  →  activeConnection(settings)   ← 永远走「使用中」那条
```

模型不知道存了几条，也无权切换。想查另一个库，只能由用户在设置页点「设为使用」再让模型重试——一次会话里跨库工作不成立。

## 2. 设计

### 2.1 每个工具加可选参数 `connection`

```jsonc
{ "connection": { "type": "string", "description": "Saved connection to run against, by its name. Defaults to the connection in use; call db_connections to see what is saved." } }
```

省略即默认连接（原「使用中」，语义未变，只是页面上改叫**默认**）。

### 2.2 新增 `db_connections`

一个只读工具，让模型发现可寻址的名字：

```jsonc
{ "active": "生产库", "connections": [
  { "id": "…", "name": "生产库", "dialect": "mysql", "host": "db.internal", "port": 3306, "database": "app", "active": true }
] }
```

**不含 `passwordEnv`**：它是凭据引用名而非密码，但它不是模型寻址需要的信息，所以不进清单——这一点由 `verify:host` 断言字段集合来守。

`id` 进清单是因为**名字不保证唯一**：重名时模型可以按 id 寻址。

### 2.3 寻址规则（`src/connections.ts`）

| 情形 | 行为 |
| --- | --- |
| 未指定 | 默认连接（`activeId`，或唯一的那条） |
| 指定名字且唯一命中 | 用它 |
| 指定名字但重名 | 拒绝，并列出候选 id |
| 指定 id | 用它 |
| 名字不存在 | 拒绝，并列出已保存的连接名 |

拒绝文本是给模型看的，所以两种"没找到"分开说：**名字打错**列已保存的名字，**没有任何连接**则指向设置页。

### 2.4 会话按连接缓存（`DatabaseAccess`）

原实现只维护一个 live session，身份变了就替换——同时用两条连接会来回重建连接池。

改为 `Map<sessionKey, LiveSession>`：

- 命中即复用，并重新插入以把它移到最近使用的一端
- 超过 `SESSION_LIMIT = 4` 时，关掉最久未用的那条（LRU）
- `dispose()` 关闭全部

`sessionKey` 含 dialect 名 + host/port/user/password/database，所以**同一部署里两种方言可以同时持有会话**。

`DatabaseAccess` 的 API 随之改为按 profile 寻址：

```ts
access.run(profile, query)
access.query(profile, sql, values?)
access.probe(profile)
```

工具层因此每个调用先解析出 profile，再取该 profile 的方言与行数上限——**行数上限属于回答这次调用的那条连接**，不再取全局的那一份。

### 2.5 face 的调整

```ts
interface DatabaseToolsFace {
  access: DatabaseAccess
  dialectFor: (profile: ConnectionProfile) => DatabaseDialect   // 之前是 dialect(): DatabaseDialect
  described: DialectFacts                                       // 描述仍按注册时写定
  settings: () => DatabaseSettings                              // 之前只给 active profile
}
```

工具自己按名字寻址，所以它需要整个 section 而不是一条 profile。

## 3. 兼容性

| 面 | 影响 |
| --- | --- |
| 既有工具调用 | 不变：不传 `connection` 就是默认连接 |
| 工具描述文本 | 不变（参数增加了 `connection`，主句未动；`verify:host` 的既有断言仍逐字通过） |
| 设置页 | 徽标文案 `使用中` → `默认`、`设为使用` → `设为默认`，语义更准确 |
| 会话开销 | 同时使用多条连接时不再反复重建连接池；上限 4 条，超出按 LRU 关闭 |

## 5. 已知边界

- **名字唯一性不强制**：设置页允许重名，重名时按 id 寻址（页面将来可以加一条唯一性校验）
- **清单不跨实例**：一个插件实例一份连接列表；多实例（多行 `ds-db`）各自独立
- **模型仍需先看才知道**：`db_connections` 是发现入口，工具描述里不会列出连接名（连接是部署数据，不属于工具契约）
