# 01_可扩展数据库类型_需求文档

## 模块定位

让 `dsh-ds-db` 从「一个 MySQL 只读插件」变成「一个只读数据库访问框架」：数据库差异全部收敛到方言（dialect）这一层，第三方开发者可以**不改本仓库、不 fork**，单独发包为一种新数据库提供连接、元数据、语法与只读规则。

本模块不新增面向模型的业务功能，它解决的是**谁能扩展、靠什么契约扩展、扩展后如何被验证**。

## 用户角色

| 角色 | 诉求 | 是否写代码 |
| --- | --- | --- |
| **A 部署方** | 换库、加库、改账号、换方言 | 否（配置 + 设置页） |
| **B 方言作者**（第三方开发者） | 「我要让 dsh 支持 ClickHouse / Oracle / SQLite」 | 是（实现接口 + 发包） |
| **C 插件维护者**（本仓库） | 保证 seam 稳定、不因新方言而破坏既有行为 | 是（seam 演进） |

## 功能列表

### F1 方言可外挂注册（现状：已支持，待加固）
- B 发布 `dsh-dialect-xxx` 包，`inject: ['databaseDialects']` 后 `register(dialect)`
- 注册是 effect，返回 disposer
- 名称冲突在注册时抛错

### F2 能力声明（现状：缺失，P0）
- 方言声明自己支持哪些能力：`createStatement` / `indexes` / `estimatedRows` / `charset` / `sample` / `explain`
- 工具在能力缺失时**降级**（省略字段 / 返回空集），而不是执行一条该库不存在的 SQL
- 模型可见描述需反映「该方言提供什么」

### F3 配置字段可扩展（现状：写死 MySQL 形状，P0）
- 通用连接字段（host/port/user/默认库/密码引用名/超时/行数上限）保持通用
- 方言可声明额外字段（如 Oracle 的 service name、SQLite 的文件路径）
- 设置页按选中方言渲染字段并做校验

### F4 分发可安装（现状：破损，P0）
- 本插件声明对 harness 包的 `peerDependencies`
- 第三方方言包声明对本插件的 `peerDependencies`
- 打包版 dsh 下 `dsh plugin --profile <name> add <pkg>` 可安装并加载

### F5 方言作者自检套件（现状：缺失，P1）
- 提供导出的测试用例集，方言作者跑一遍就知道自己的实现是否合规
- 覆盖：只读判定、行数上界、标识符引用、元数据投影、能力一致性

### F6 参考实现与模板（P1）
- PostgreSQL 作为「第一个非内置方言」的完整范例
- 模板仓库 `dsh-dialect-template`

### F7 工具集可开放（P2）
- 新增工具（采样、执行计划、关系图）可由方言按需提供底层查询
- 未提供时该工具不注册或明确拒绝

### F8 结果呈现可扩展（P2）✅
- Web 侧结果卡片：已完成 —— `db_query` / `db_sample` 画结果表，`db_tables` / `db_databases` 画清单；`db_describe` / `db_explain` 保持通用行
- 调用卡片（`presentCall` / `presentResult`）：**不做** —— 内置 Web 客户端不消费它们；呈现面在 client 插件里注册到 `tool.call.toolview`

## 用户故事

- 作为**部署方**，我希望在设置页切换数据库类型后工具立刻访问新库，以便不用重启插件。
- 作为**方言作者**，我希望只实现一个接口就能让 4 个既有工具跑在我的数据库上，以便不必重写工具层。
- 作为**方言作者**，我希望我的数据库不支持 `SHOW CREATE TABLE` 时工具不会报错，而是优雅降级，以便我不必伪造 SQL。
- 作为**方言作者**，我希望我的连接表单能出现 service name 这样的专属字段，以便用户能配通我的库。
- 作为**方言作者**，我希望有一个自检套件，以便发包前知道自己实现得对不对。
- 作为**插件维护者**，我希望新方言不会改变既有 MySQL 用户的任何行为，以便兼容性可控。

## 字段说明

| 字段 | 含义 |
| --- | --- |
| `DatabaseDialect.name` | 注册表键，配置里 `dialect:` 引用它 |
| `DatabaseDialect.label` | 模型可见的自称 |
| `DatabaseDialect.capabilities` | 本方言支持的能力集合（新增） |
| `DatabaseDialect.configFields` | 本方言额外的连接字段声明（新增） |
| `DatabaseDialect.rules` | 只读判定的词法与禁止项 |
| `ConnectionProfile` | 一条保存的连接（id / name / dialect / 通用字段 / extra） |

## 业务规则

1. **只读姿态三层不变**：语句判定 → 协议层约束 → 部署方只读账号。新方言必须提供 `rules`，这是安全红线。
2. **能力缺失必须降级，不得伪造**：方言不支持某能力时，工具省略该段输出并在描述中说明，不允许返回假数据。
3. **方言名称唯一**：重复注册即抛错。
4. **方言名未注册时首次调用报错**并列出已注册方言（注册表由本插件提供，加载期无法知道最终集合）。
5. **配置兼容性**：既有保存的连接（MySQL 形状）在升级后必须仍然可用，不允许用户重新录入。

## 边界场景

| 场景 | 期望行为 |
| --- | --- |
| 方言在插件之后才注册 | 调用立即生效；工具描述文案滞后到下次重载（已知取舍，需在文档明示） |
| 连接选中的方言未注册 | 首次调用报错，列出已注册方言 |
| 方言不支持 `createStatement` | `db_describe` 省略 `createStatement` 字段，其余照常 |
| 方言不支持 `estimatedRows` | `db_tables` 该项为 `null` |
| 方言声明了未知能力键 | 注册时校验拒绝 |
| 保存的连接缺少方言新增的必填字段 | 工具调用报错并指明缺哪个字段 |
| 用户删除全部连接 | 工具调用报「没有保存的连接」而非崩溃 |
| 第三方方言包未声明依赖 | 安装后 `ERR_MODULE_NOT_FOUND`——由 F4 的模板与文档规避 |

## 验收标准

| 编号 | 标准 | 可验证方式 |
| --- | --- | --- |
| AC1 | 一个独立包注册方言后，4 个工具全部能跑，本仓库零改动 | `verify:host` 中的「后注册方言」用例（已有）扩展为独立包形态 |
| AC2 | 缺失 `createStatement` 的方言，`db_describe` 正常返回且不报错 | 单测 + `verify:host` |
| AC3 | 设置页按方言渲染额外字段，且保存后工具能读到 | 手动验收 + 契约测试 |
| AC4 | 本插件 `peerDependencies` 声明完整，打包版 dsh 可 `plugin add` 安装 | 在打包 dsh 上实测 |
| AC5 | 方言作者自检套件存在且对本插件自带 MySQL 方言全绿 | `npm test` 复用该套件 |
| AC6 | 既有 MySQL 连接升级后无需重新录入 | 迁移用例 |
| AC7 | `typecheck` + `npm test` + `verify:host` 全绿 | CI 命令 |

## 优先级

- **P0（必须）**：F2 能力声明、F3 配置字段扩展、F4 分发可安装
- **P1（重要）**：F5 自检套件、F6 PostgreSQL 参考实现与模板仓库
- **P2（一般）**：F7 工具集开放、F8 结果卡片
- **P3（可选）**：写操作（需审批与写账号，属产品形态变化，单独评估）

## 技术约束

- ESM only；Node `^22.19 || >=24`
- 不得破坏既有 cordis.yml 组合层配置（平铺字段保持兼容）
- 不得把 harness 源码路径写进运行时（宿主解析）
- 浏览器半边是构建产物，改 `src/client` 必须重建
- 只读是安全基线，任何方言不得放宽

## 依赖关系

- 依赖宿主服务：`ctx.tools`、`ctx.settings`、`ctx.credentials`、`ctx.connection`、`ctx.databaseDialects`（本插件提供）
- 依赖宿主构建链：`dsh.client.platform` + `exports["./client"]` 的模块扫描
- 被依赖：第三方方言包（F4 打通后）
